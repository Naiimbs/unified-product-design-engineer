# Unified Product Design & UX Engineering

A multi-platform adaptive skill for senior product design, UX/UI engineering, visual screen understanding, application auditing, accessibility, responsive design, implementation, and evidence-based quality validation.

## Package contents
- `SKILL.md` — master operating instructions
- `references/` — 18 practical reference guides
- `workflows/` — 10 repeatable execution workflows
- `templates/` — 11 reusable working templates
- `package-manifest.json` — package metadata
- `INSTALLATION.md` and `CHANGELOG.md`

## What's new in v1.2.0
- **Visual Intelligence:** structured screen, component, state, and asset interpretation with explicit confidence labels and evidence limitations.
- **Validation Lab:** repeatable audit, redesign, and new-flow test cases.
- **Scoring rubric:** 0–4 quality dimensions, evidence levels, pass/revise/block gates, and critical-failure overrides.
- **Visual inventory template:** capture context, screen structure, asset mapping, interaction states, localization, and accessibility cues.
- Cleaned duplicated visual-asset protocol text and duplicate index entries in the master skill.

## Install
Keep `SKILL.md` and the three resource directories together. Copy the folder into the skills location supported by your agent, then invoke it using that platform's skill mechanism. Adapt metadata/frontmatter only if the platform requires a different convention.

## Use
Ask naturally: “Audit this portal”, “Map the components and assets in this screen”, “Redesign this notification without losing its existing icon”, “Design the core user flow”, or “Run the Validation Lab on these three cases”. The skill selects an adaptive workflow based on the request and available tools.

## Visual context preservation
When redesigning existing UI, inventory icons, images, illustrations, logos and media; preserve correct assets in their original component and data instance; and verify responsive crops, accessibility metadata and shared-component effects.

## Evidence and safety
Audits are read-only. Changes to existing assets require clear authorization. Publishing and destructive actions require explicit approval. Findings, source claims, and test claims must be evidence-based. A screenshot is not proof of source bindings, keyboard behavior, or WCAG conformance.
